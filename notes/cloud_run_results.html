IBM Quantum cloud runs · October and November 2026

IBM Readout Memory Tests

Six qubits of IBM's ibm_kingston processor were read out thousands of times in a row to look for a hidden variable that persists between measurements, in two models built for this project. Neither model shows a signal. The ordinary effects the runs uncovered, leakage and readout memory, matter for error correction. In November, two runs on ibm_fez read the same memory for qubits near |0⟩ or |1⟩, as an error-correction syndrome qubit is read.

What the hardware showed
Leakage and readout memory

Leakage episodes lasting tens of microseconds, entering during idle time as well as during readouts, plus readout memory of either sign on four qubits.

What was tested

Donadi and Hossenfelder's 2022 toy model picks each measurement outcome by comparing a hidden random number with the Born probability, but it says nothing about how that number changes between measurements. A draft theory note in this project adds two minimal completions: the hidden variable belongs either to the detector or to the qubit, and survives from one readout to the next with probability w. Both keep every single readout at its Born value, so the only signature is a correlation between successive outcomes.

These completions are constructions made for this project, not proposals by Donadi or Hossenfelder. The runs bound these two models on this processor and readout. They do not test superdeterminism in general or Hossenfelder's 2025 collapse model.

How the runs worked

  • Each qubit ran a chain of 16 to 66 readouts per shot with no resets in between. Every setting was a frame phase on the same two π/2 pulses, so ordinary physics can only produce smooth, low-order dependence on the preparation angle.
  • Random relabeling of each readout separates detector-carried effects from qubit-carried ones, and a scan of the preparation angle looks for the cusp that a threshold hidden variable produces.
  • The design and the analysis code were committed before any data existed, for the main run and again for the follow-up.
  • QPU time charged: 12 s for the pilot, 2 s for a first main-run attempt that IBM rejected before running, 388 s for the main run and 178 s for the leak-tagged follow-up. That is 580 s of the free plan's 600 s per 28 days.

Leakage explains the shot-wide correlation

In the main run, neighboring readouts were correlated on every qubit, and the correlation stayed nearly as strong two to eight readouts apart. A hidden variable that persists from readout to readout cannot produce that pattern. The follow-up placed two flip pulses after every four readouts: a qubit that has leaked out of its two levels reads "1" three times in a row instead of alternating, which tags the block.

When the readout rate dropped by a factor of 3.8, the leaked fraction changed by factors of 0.59 to 1.28, between what leakage caused only by readouts (0.35 to 0.59) and leakage that only builds up with time (1.3 to 2.2) would give once the buildup within each shot is counted (exploratory). Both contribute. Lifetimes from the tags are 9 to 124 µs; these are lower limits.

19 November: memory on eigenstate readouts

A syndrome qubit in error correction is read out near a definite state, |0⟩ or |1⟩, rather than on the equator as in October. On 19 November 2026 a pre-registered run on eight ibm_fez qubits added a repeat step and a flip step after each leak check: the three October fez qubits with positive equator memory as controls, and five fresh qubits. Each qubit's result is read against its own simulated conventional null, built from readout errors measured in the same run, its T1 and its leakage. A qubit reads memory only beyond three standard errors on both selection masks with one sign.

4 of the 8 qubits read memory on eigenstate readouts, of both signs, among the fresh qubits as well as the controls, so on this device the effect is not limited to qubits picked for it. On the controls, the equator values repeat October's five weeks later, but they do not predict the eigenstate readings qubit by qubit. The run used 415 s of QPU time in nine jobs. The null is a model built here, and its readout errors came from the first readout of each shot.

An exploratory test chosen after the data shows that this calibration was the null's main error. On every qubit, the first readout of a shot misreads |1⟩ 0.10 to 0.43 percentage points more often than the readouts inside the chain, with no trend along the chain. Against a null built from in-chain errors, 7 of the 8 qubits read negative memory and 1 positive: a |1⟩ read again after a "1" fails more often than a freshly flipped |1⟩, beyond T1 relaxation. That attribution assumes memory acts only after a "1".

A repeat on the same qubits the same afternoon, with this reading and its replication rules committed before the data (136 s of QPU time), confirmed it. 7 of the 8 qubits replicate the in-chain reading with the same sign, one is inconclusive at the repeat's smaller sample, and none drifted between the runs. The first-readout offset replicates on all 8 qubits, at 0.12 to 0.64 points.

Why it matters beyond the models

Leakage that lasts for many readout rounds and readout memory at the 10−3 level are the kinds of correlated measurement errors that degrade surface-code memory in simulations by Kam and colleagues (Quantum Sci. Technol., 2025). Seeing them took about 107 readout pairs per qubit, well within a free cloud allowance.
